# report.html 읽는 법 — TIA 인터랙티브 리포트 해설

`tia report`가 생성하는 자기완결형(self-contained) HTML 리포트 [`report.html`](report.html)를 화면
그대로 해설한다. 외부 요청 없이 브라우저로 바로 열리고, 같은 입력이면 항상 같은 결과가 나온다.
입력은 `testwise.json`(필수)과 선택 입력 `impact.json · scenarios.json · flaky.json · prod-files.txt`다.

> **한 줄 요약:** 페이지 하나가 질문 하나에 답한다. 모든 수치는 실측 per-test 커버리지에서 계산한다.

| 페이지 | 답하는 질문 | 필요한 입력 |
|---|---|---|
| 변경 영향 | 이번 변경이면 테스트를 몇 개 돌려야 하나 | `--impact`(실제 diff) 또는 `--scenarios`(데모). **둘 다 없으면 페이지가 없다** |
| 연결 구조 | 테스트와 프로덕션 코드는 어떻게 연결돼 있나 | `testwise.json` (+ 사각지대 목록은 `--prod-files`) |
| 커버리지 지도 | 어디가 지켜지고 어디가 비어 있나 | `testwise.json` (+ `--prod-files`) |
| 안정성 | 이 측정 결과를 믿어도 되나 | `--flaky` |

---

## 상단 바

- **SUT 이름**과 **indexed commit** — per-test 커버리지를 저장한 베이스라인 커밋. 모든 선별 판단의 기준점이다.
- **수치** — 테스트 수, 테스트가 한 번이라도 실행한 프로덕션 파일 수 / 전체, 사각지대 파일 수.
- **페이지 전환** — 데이터가 있는 페이지만 나온다.

## 공통 동작

- **묶음과 드릴다운.** 한 화면에는 한쪽에 최대 26개 항목만 올린다. 그보다 많으면 패키지·클래스
  묶음으로 보여주고, 묶음을 누르면 한 단계 안으로 들어간다. 위쪽 경로(`전체 › billing › …`)를 눌러
  되돌아간다. 묶음이 26개를 넘으면 큰 순으로 25개와 "그 외 N개"로 나온다.
- **전체 목록.** 목록은 12개까지만 보여주고 "N개 전체 보기 →"로 전체 목록 페이지에 연결한다.
  전체 목록은 50개씩 쪽으로 나뉘고 이름으로 거를 수 있다.
- **링크.** 테스트 하나가 실행한 파일 이름은 JaCoCo HTML 커버리지의 첫 커버 라인(`#L<n>`)으로,
  테스트 이름은 로컬 테스트 소스(`file://…`)로 연결된다.
- **색.** 파랑 = 정밀 선별, 노랑(사각형) = 보수적 선별, 빨강(빈 원) = 사각지대.

## 변경 영향 — "이번 변경이면 테스트를 몇 개 돌려야 하나"

**실제 diff (`--impact`).** `tia impact --format json` 출력을 넘긴 실행이다. 첫 줄이 결론이다:
"이번 변경 N개 파일이면 M개 중 K개만 돌리면 된다." 오른쪽 링은 실행 절감률이다.

왼쪽 목록은 **조치가 필요한 순서**다.

| 그룹 | 뜻 | 왜 이 순서인가 |
|---|---|---|
| 보호하는 테스트 없음 | 변경 라인을 지나는 테스트가 0개(사각지대) | 테스트가 통과해도 이 변경은 검증되지 않았다 |
| 전체 실행을 유발 | 신규 `.java`·비-코드 변경이라 커버리지에 매핑할 수 없음 → 보수적 전체 선택 | 절감이 사라진 이유. 첫 줄 아래에 "이 변경을 빼면 몇 개"가 함께 나온다 |
| 정밀 선별 | 변경 라인 ∩ 테스트의 커버 라인 ≠ ∅ 인 테스트만 선별 | 선별된 테스트가 많은 순 |

"이번 변경 전체"는 모든 변경 파일의 합이고, 파일 하나를 누르면 그 파일만의 결과가 나온다.
가운데 점(또는 묶음별 막대)은 어느 테스트가 실행되고 어느 테스트를 건너뛰는지 보여준다.

**데모 시나리오 (`--scenarios`).** `--impact`가 없고 시나리오가 있으면 이 페이지는 시나리오 목록으로
나온다. 시나리오는 **서로 독립된 가상 변경**(파일·라인에 `// tia-probe` 한 줄을 넣은 합성 diff)이며
한 PR의 변경 파일이 아니므로 합계 행이 없다. 이 저장소의 `report.html`이 이 형태다.

## 연결 구조 — "테스트와 프로덕션 코드는 어떻게 연결돼 있나"

왼쪽은 테스트, 오른쪽은 테스트가 실제로 실행한 프로덕션 파일이다. 선은 "실행했다"이고 굵기는 실행
라인 수다.

- 노드에 올리면 그 노드의 연결만 남고, 누르면 고정된다. 오른쪽 패널에 연결 상대가 많은 순으로 나온다.
- 연결이 많은 파일일수록 변경 시 영향 범위가 넓은 **핫스팟**이다.
- 위의 변경 항목을 누르면 그 변경 파일과 선별된 테스트가 켜진다.
- 규모가 클 때는 "사례 바로 보기"로 **여러 파일 묶음에 걸친 테스트 하나**, **여러 테스트 묶음이
  실행하는 파일 하나**를 바로 볼 수 있다(한쪽만 드릴다운한 화면).

아래 **어떤 테스트도 닿지 않는 파일**은 사각지대 목록이다. 여기를 고치면 정밀 선별에서 0개가 나온다.
`--prod-files`를 넘기지 않으면 계산할 수 없다는 안내가, 사각지대가 없으면 "전체 커버"가 나온다.

## 커버리지 지도 — "어디가 지켜지고 어디가 비어 있나"

행은 테스트, 열은 프로덕션 파일이고 칸의 진하기는 실행 라인 수다(정확한 값은 칸에 올리면 나온다).

- **세로줄이 긴 열**은 여러 테스트가 공유하는 코드다.
- **칸을 누르면** 오른쪽 패널이 그 칸의 실행 라인·연결 수와 테스트·파일 목록으로 바뀐다.
- **행·열 이름을 누르면** 그 묶음 안으로 들어간다.
- 오른쪽 **도달 범위**는 패키지별로 테스트가 닿은 파일과 닿지 않은 파일(빗금 또는 빈 막대)을 보여준다.

## 안정성 — "이 측정 결과를 믿어도 되나"

- **실측** — 같은 스위트를 N회 실제로 돌려 결과(Pass/Fail)가 바뀐 테스트 수. 0이면 N번 내내 같은
  결과였다는 뜻이다.
- **검출기 대조군** — 실제 실행이 아니다. 한 테스트의 결과를 일부러 Pass→Fail→Pass로 뒤집은 가짜
  실행을 검출기에 넣어, 검출기가 그것을 잡아내는지 확인한다. 실측과 다른 것을 재므로 값이 같을
  필요가 없다. 대조군을 잡아낸다는 사실이 실측의 0이 "검출기 고장으로 0"이 아님을 보증한다.

## 로컬 링크에 관한 주의

JaCoCo 딥링크와 테스트 소스 링크는 **생성한 머신의 경로** 기준이다. 커밋된 `report.html`은 샘플이며,
본인 환경에서 `run-petclinic-tia.sh`를 실행하면 올바른 경로로 재생성된다. JaCoCo 딥링크는 같은
실행에서 만들어진 `petclinic-demo/jacoco/`(gitignore됨)가 옆에 있어야 동작한다.
