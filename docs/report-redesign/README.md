# TIA 리포트 리디자인 시안

`tia-report-samples.html` 은 `tia report` 가 생성하는 HTML 리포트(`tia-core/src/main/resources/report-template.html`)를
대체하기 위한 **디자인 시안**이다. 브라우저로 바로 열 수 있다.

> 이 파일은 TIA 가 생성한 산출물이 아니다. 손으로 작성한 목업이며, `tia report` 의 출력은 아직 기존 리포트다.

## 무엇이 실측이고 무엇이 가정인가

| 항목 | 출처 |
|---|---|
| `실측 24` 데이터 | `petclinic-demo/report.html` 의 `D` 모델에서 추출 (로컬 절대경로 `testSrc` 는 제거) |
| `합성 1,000` / `합성 10,000` | 브라우저에서 고정 시드로 만든 가짜 데이터. 규모 확인용이며 실제 리포트에는 넣지 않는다 |
| "이번 변경 전체" | 데모 시나리오 7개를 한 PR 의 변경 파일로 **가정**한 것. 실제 diff 결과가 아니다 |
| 글꼴 | 시안은 Google Fonts 를 불러온다. 실제 리포트는 자기완결형이어야 하므로 시스템 글꼴로 바꾼다 |

## 확정된 결정

- **페이지마다 질문 하나.**
  - 변경 영향: 이번 변경이면 테스트를 몇 개 돌려야 하나 (첫 화면, 리더 우선)
  - 연결 구조: 테스트와 프로덕션 코드는 어떻게 연결돼 있나
  - 커버리지 지도: 어디가 지켜지고 어디가 비어 있나
  - 안정성: 이 측정 결과를 믿어도 되나
- **diff 가 없는 실행(베이스라인 인덱싱)에는 "변경 영향" 페이지가 없다.**
- **변경 파일 정렬**: 보호하는 테스트 없음 → 전체 실행을 유발 → 정밀 선별(선별 많은 순).
- **규모 대응**: 한 화면에 한쪽 최대 26개 항목. 넘으면 모듈·패키지·클래스 묶음으로 보여주고 눌러서 내려간다.
  "외 N개" 는 쓰지 않고 전체 목록 페이지(50개씩, 이름으로 거르기)로 연결한다.
- **자기완결형 유지**: 외부 요청 0, HTML 한 장.

## 후속 과제

- [ ] 시안을 `report-template.html` 로 이식하고 `ReportBuilder` 모델을 보강한다 (실제 변경 파일별 선별 결과, 합성 데이터·시안 전환 바 제거).
- [ ] 리포트 용량: 모델의 `perTest` 와 `reverse` 가 같은 관계를 두 번 담는다. 대형 SUT 에서는 `reverse` 를 빼고 브라우저에서 계산한다.
- [ ] 26개를 넘는 "그 외" 묶음 안으로 들어가는 방법(검색 또는 다음 쪽).
- [ ] 기존 리포트의 JaCoCo 라인 딥링크, 테스트 소스 링크 복원.
- [ ] run 누적 추세 화면(절감률·사각지대 추이). 단일 run 리포트 범위 밖.
- [ ] **본체 누락**: 커버한 파일이 0개인 테스트는 `CoverageStore.save()` 에서 행이 생기지 않아 인덱스에서 사라진다.
  그 결과 `ImpactAnalyzer` 의 "보수적 전체 선택"이 petclinic 에서 24개가 아니라 21개를 고른다
  (`*RequiresAuthentication` 3개 누락). 리포트와 별도로 수정이 필요하다.
